# Issue #5: Ship follow-up audit

Baseline: [`main` at `1655460`](https://github.com/abominableenterprise/yetikit/commit/1655460e5adfe18a2a85184941e855ef84c78f00). Read the body of [issue #5](https://github.com/abominableenterprise/yetikit/issues/5), all 23 comments across three API pages, and the disposition notes in [PR #3](https://github.com/abominableenterprise/yetikit/pull/3). Duplicate reports are combined below. The original PR's rejected deferrals are also accounted for by the path normalization, standalone keeps, shared cleanup and activation-gate entries below.

**[#182](https://github.com/abominableenterprise/yetikit/pull/182) fixed two ways `test pr` can report green without running a changed Gfx fixture:** multiline category attributes and noncanonical builder dependency keys. Both were reproduced on the baseline with synthetic fixtures. The open rows below remain in #5; do not close the issue. Open-row repro notes are code-inspection recipes, not claims of real-host reproduction. Validation uses synthetic fixtures only.

## PR test selection and evidence

| Finding | Status and evidence |
| --- | --- |
| [Whitespace and multiline Gfx attributes](https://github.com/abominableenterprise/yetikit/issues/5#issuecomment-6650042632) | **Fixed by [#182](https://github.com/abominableenterprise/yetikit/pull/182).** [#157](https://github.com/abominableenterprise/yetikit/pull/157) already accepted whitespace on a single line, but `cs_classes` still matched one line at a time. It now requires both plus the spaced class, without selecting the untagged class. |
| [Noncanonical builder dependency keys](https://github.com/abominableenterprise/yetikit/issues/5#issuecomment-6650651544) | **Fixed by [#182](https://github.com/abominableenterprise/yetikit/pull/182).** [#124](https://github.com/abominableenterprise/yetikit/pull/124) preserved literal Git path spellings but did not canonicalize the JSON keys. The updated [literal-roots fixture](../../../Tools/ship/tests/linux-unity-test-pr-roots-literal.test.sh) shows equivalent keys with `./` and `//` selecting neither dependency before the fix, for both tracked and untracked builders. It now requires both mapped fixtures, preserving Unicode and literal backslashes. |
| [Missing/zero initial or retry evidence](https://github.com/abominableenterprise/yetikit/issues/5#issuecomment-6650037536) | **Fixed on main** by [`f996616`](https://github.com/abominableenterprise/yetikit/commit/f996616) and [#121](https://github.com/abominableenterprise/yetikit/pull/121). [Missing](../../../Tools/ship/tests/linux-unity-evidence-invalid-missing.test.sh), [malformed](../../../Tools/ship/tests/linux-unity-evidence-invalid-malformed.test.sh), [retry evidence](../../../Tools/ship/tests/linux-unity-evidence-retry.test.sh) and [retry coverage](../../../Tools/ship/tests/linux-unity-flakes-retry-coverage.test.sh) fixtures require real XML and successful execution of the original failures. [Filtered empty](../../../Tools/ship/tests/linux-unity-evidence-filtered-empty.test.sh) covers the deliberate exception for an empty category pass in filtered EditMode, not a green run with no tests across both passes. |
| [Abnormal process exit with complete flake XML](https://github.com/abominableenterprise/yetikit/issues/5#issuecomment-6650038850) | **Still open.** `run_pass` treats any nonzero exit with qualifying XML as retryable. The existing [crash fixture](../../../Tools/ship/tests/linux-unity-flakes-crashes.test.sh) has missing/stale XML, not this combination. |
