# Review focus

Apply to all Unity C# changes; report concrete defects with file/line, impact and a minimal fix.
- Hot loops (Update/FixedUpdate/LateUpdate, per-frame callbacks and repeated physics paths): no managed allocations, LINQ, GetComponent, Find APIs or Camera.main. Cache references outside hot loops; reuse buffers; avoid closures, boxing and per-frame string formatting.
- Every event `+=` has a matching `-=`; balance disposable hook lifetimes too. Test repeated enable/disable and scene reloads.
- Reset static state using `[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.SubsystemRegistration)]`; verify domain-reload-disabled behavior, including duplicate listeners.
- Keep dev code in `Game.Dev`, define-constrained by `YETIKIT_DEV`; no release references, components or dev-only permissions. Hooks register only at the composition root.
- Never hand-edit scene YAML; prefer prefab/catalog edits and small per-area test scenes/builders. Preserve serialized references and GUIDs.
- Serialized field renames require `FormerlySerializedAs`; check migration and existing prefab values, not only compilation.
- One job per file; keep sources below ~800 lines / 50 KB and PRs focused. Bug fixes require a failing-first regression test.
- Never patch `Tools/yetikit/` or kit packages in the consumer. Fix upstream and bump all pins/tools coherently to one tag.
- Kit tooling/APIs are planned, not shipped: [planned API, see docs/design.md](https://github.com/abominableenterprise/yetikit/blob/main/docs/design.md). Do not accept claimed validation from nonexistent tools.
- No secrets, private identity or real playtest media in public changes; fixtures must be synthetic.
- Follow the exact review/merge policy in `AGENTS.md`; do not weaken findings or invent successful test results.
